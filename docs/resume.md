# 简历与面试材料

> 用途：把项目压缩成可投递的条目，以及面试时经得起追问的细节。所有数字都来自仓库里的测试记录与线上实测，没有估算。

## 1. 一句话

个人开发并上线的 AI 编程工作台：四条任务链路（生成 / 解释 / 调试 / 重构）共用一套流式协议与结果结构，接入 Supabase Auth + RLS 做账号级数据隔离。

## 2. 简历条目（可直接用）

- 独立设计并上线 AI 编程工作台（Next.js 16 / React 19 / TypeScript / Supabase），支持代码生成、解释、调试、重构四类任务，统一 SSE 流式协议，线上首字延迟 **1.7s**。
- 实现**账号级数据隔离**：请求路径全程只使用 publishable key + 用户 access token，三张业务表配置 RLS 策略；跨账号读取返回 404（而非 403，避免泄露资源存在性）。
- 上下文由服务端持有并按预算裁剪（最近 10 条 / 单条 4000 字 / 总量 24000 字），客户端只传会话 ID，避免刷新或伪造请求导致上下文失真。
- 建立**三层测试体系**：220 个单元与组件用例、25 个端到端用例（含真实模型主链路）、15 项迁移与 RLS 自检，覆盖率行 **95.9%** / 分支 **83.5%**。
- 完成安全加固与交付：nonce + `strict-dynamic` 的 CSP、HSTS 等响应头、密钥扫描脚本（540 文件 0 命中）、生产依赖 0 漏洞；部署至 Vercel 并通过线上验收。

> 若简历只能放两条：选「账号级数据隔离（RLS）」与「三层测试 + 线上流式实测」——前者体现数据边界意识，后者体现工程完成度。

## 4. 三个能讲深的技术决策

### 4.1 为什么用 RLS 而不是在代码里过滤

- **做法**：所有业务查询用「publishable key + 用户 token」的客户端，secret key 只在脚本里出现。
- **收益**：安全性不依赖"每个仓储函数都记得加 `where owner_id = ...`"。漏写不会泄露数据，只会查不到。
- **细节**：`messages` 表没有 `owner_id`，四类策略统一用 `exists` 校验父会话归属——多存一列就多一处可能与父会话不一致的地方。
- **代价**：每次读消息多一次主键查找；策略写错会导致"什么都查不到"，需要靠 `pnpm verify:migrations` 在本地验证。

### 4.2 为什么历史不交给客户端

- 早期版本让客户端上传 `history` 数组，问题有两个：可以被伪造、刷新后拼装逻辑容易与数据库不一致。
- 现在只传 `conversationId`，历史从数据库按 `seq` 读，再按预算裁剪。
- **主动说局限**：预算是字符数不是 token 数，只是成本护栏，不精确。

### 4.3 流式协议怎么设计

- 四类事件：`meta`（请求 ID / 模型 / 上下文条数）、`delta`（增量文本）、`done`（真实 usage）、`error`（八类错误码 + 是否可重试）。
- 关闭流式时上游改非流式，但**对浏览器仍是同样的事件序列**，前端无需分支。
- 重试只发生在首字节之前，避免用户看到重复内容。

## 5. 常见追问与回答要点

| 追问 | 回答要点 |
|---|---|
| 怎么保证 A 看不到 B 的数据？ | 接口层用用户 token 访问数据库，RLS 策略 `owner_id = auth.uid()`；越权查询返回空行 → 404。双账号 e2e + 直连 PostgREST 两条路径都验证过。 |
| CSP 为什么样式还留 `unsafe-inline`？ | Turbopack 开发态 HMR 与 next-themes 写行内样式；脚本没有放开，风险主要来自脚本执行。这是有意识的取舍，写在 docs/security.md。 |
| 为什么不用 offset 分页？ | 会话按 `last_message_at` 排序，每来一条消息就变；offset 会重复/漏条。改用 `(last_message_at, id)` 复合游标。 |
| 限流怎么做的？ | 进程内内存计数，按 IP。**明确说这是限制**：多实例部署时实际额度 = 配置 × 实例数，生产要换 Redis/网关。 |
| 测试覆盖率多少？ | 行 95.9%、分支 83.5%，只统计 10 个纯函数模块；API 路由靠 e2e 与 curl 实测，不硬凑数字。 |
| 最大的坑？ | 三个：Next 16 默认拦截 `127.0.0.1` 的 dev 资源导致"页面正常但点击全无反应"；`signOut()` 默认全局吊销导致 e2e 互相污染；迁移里 `messages` 没有 `owner_id` 导致整批回滚。都写进了 docs。 |
| 有什么没做？ | 无找回密码、无 MFA、限流单实例、CSP 无上报端点、未做 SAST/DAST。README 与 docs/security.md 里逐条列了。 |

## 6. 面试现场可展示的顺序

1. 打开线上地址，走一遍生成（30 秒）；
2. 打开 `/api/health`，说明配置自检；
3. 浏览器 DevTools → Network → 看 SSE 分片；
4. 切第二个账号，访问第一个账号的会话 → 404；
5. 打开 `docs/security.md` 与 `docs/testing.md`，说明边界与未覆盖项。
